Project Sizes

Configure the budget thresholds that classify projects by T-shirt size — XS through XL.

Project Sizes lets administrators define the budget boundaries for each size band. Every estimate in the system automatically displays a size badge (XS, S, M, L, or XL) based on its total cost. Changing these thresholds immediately affects how all estimates are classified — no re-saving of individual estimates is required.

Navigate to Project → Configurations → Project Sizes to access this screen.

Budget variance per size

Each size tier has a configurable Budget Variance (%) — the percentage within which a project of that size is considered On Budget (GREEN) when comparing its actual budget against the linked estimate's total cost. Variance beyond this band but within the global risk threshold shows as AMBER; beyond the risk threshold shows as RED.

Budget risk threshold

The Budget Risk Threshold (%) is a single global setting that defines the AMBER/RED boundary for all project sizes. When the cost variance exceeds the per-size budget variance but stays within this threshold the risk status is AMBER; beyond it the status is RED.

SettingDefaultEffect
Budget Risk Threshold 10.0 % Cost variance < per-size variance → GREEN

These settings power the budget risk badges on Project Budgets. The size-specific variance and global risk threshold work together to produce the GREEN / AMBER / RED status shown on each budget record. See Project Budgets for details on how the risk status is displayed and what each colour means.

Updating the thresholds

  1. Navigate to Project → Configurations → Project Sizes.
  2. Each tier card (XS, S, M, L) shows two editable fields: Max Amount (£) and Budget Variance (%). The XL card shows only the Budget Variance (%) field — its max amount is derived automatically.
  3. Update the Max Amount fields to change where each size band starts and ends. The range hints beneath each field update live as you type.
  4. Update the Budget Variance (%) fields to change how tightly each size tier is evaluated for budget risk.
  5. Update the Budget Risk Threshold (%) field (shown below the size cards) to change the global AMBER/RED boundary.
  6. Review all values and click Save Changes. All thresholds take effect immediately across all estimates and budget records in the system.

Live range hints

As you type in any Max Amount field, the range label underneath it updates in real time — showing the exact currency boundaries for that tier. The XL card's range also updates live to reflect the new starting point whenever you change the L max amount. Use this to verify your thresholds before committing.

Rules for valid thresholds

  • All four Max Amount values (XS, S, M, L) must be positive integers — zero and negative amounts are not accepted.
  • Max Amount values must be in strictly ascending order: XS < S < M < L. Equal values between adjacent tiers are not allowed.
  • Budget Variance values must be positive decimal numbers greater than zero.
  • The Budget Risk Threshold must be a positive decimal number greater than zero.
  • If any value fails validation when you click Save, an error is shown before anything is sent to the server — no partial saves occur.
Changes affect all estimates immediately. Saving new thresholds re-classifies every estimate in the system on the next load. An estimate that was previously M may show as L after you raise the M boundary. There is no preview of how many estimates will change — plan threshold updates carefully.

Who can update Project Sizes

Only users with the Change Configuration permission can view the editable fields and save changes. Users without this permission can still navigate to the page and see the current thresholds as read-only values — but cannot modify them. The Project Sizes menu item is only visible in the navigation when the user has this permission.

Common errors
"Amounts must be in ascending order: XS < S < M < L" — one or more of your values is equal to or greater than the next tier. Review all four fields side by side and ensure each is strictly larger than the one before it.

"This field is required" — all Max Amount and Budget Variance fields must contain a value before saving. Clearing any field and clicking Save will trigger this validation.

"S max amount must be greater than XS max amount" — the S value you entered is less than or equal to the XS value. Adjust accordingly.

"Budget variance must be a positive number" — Budget Variance and the Budget Risk Threshold must be greater than zero. Enter a decimal value such as 0.5 or 10.0.
Tip: Use round numbers that reflect how your organisation thinks about project scale — for example multiples of £25k or £50k. The range hints on the screen show the exact boundaries in real time, so you can see what you are setting before you save.

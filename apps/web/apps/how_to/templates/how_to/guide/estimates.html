Project Estimates

Versioned effort and cost estimates with a governed approval workflow.

An estimate records how many effort days a project requires, the day rate, and a contingency allowance. You can hold multiple estimate versions as scope evolves. Each version passes through a defined review and approval workflow. Only one version is Approved at any time — approving a newer version automatically supersedes the previous one. The Approved version drives budget and financial views.

Estimate fields

FieldWhat it means
Estimate DaysThe total effort required, in working days.
Contingency %A percentage buffer added on top of the base cost. Defaults to 0.
Day RateAutomatically taken from the current sprint configuration at the moment the estimate is created. It is snapshotted and does not change if the sprint day rate changes later.
Total CostCalculated automatically: Estimate Days × Day Rate × (1 + Contingency % ÷ 100).
SizeA T-shirt size badge (XS / S / M / L / XL) derived from the total cost against configured thresholds. Updated automatically when the cost changes.
Shared ByRequired. The person or people who shared this estimate with stakeholders.
Reviewed ByRequired when advancing to Reviewed or beyond. One or more internal reviewers.
Estimate LinkOptional URL to a detailed estimate document (e.g. a Confluence page or spreadsheet). Clicking the estimate row in the table opens this link.
NoteA free-text note recorded in the version history at the time of creation or update.

Creating an estimate

  1. Open the project and click the Estimates tab.
  2. Click Create Estimate.
  3. Enter the number of Estimate Days.
  4. Enter a Contingency % if applicable (leave blank for 0).
  5. Select one or more people in Shared By — this field is required.
  6. Optionally paste an Estimate Link URL and add a Note.
  7. Click Save. The estimate is created in Draft status. The version number, day rate, total cost, and size are set automatically.
Versions are project-scoped. Each new estimate on the same project gets the next version number (v1, v2, v3 …). Version numbers are never reused, even if an intermediate version is deleted.

Estimate status workflow

StatusWhat it means
DraftBeing prepared. Not yet shared externally. Can be edited or deleted.
ReviewedReviewed internally. At least one reviewer must be named before advancing.
SharedSent to stakeholders for sign-off.
ApprovedFormally agreed. Locked for editing and deletion. Only one estimate per project can be Approved at a time.
SupersededReplaced by a newer Approved version. Kept permanently for historical reference. Locked.

Advancing an estimate through the workflow

Use the Advance action on any estimate row. Each step moves the estimate to the next status. The action is hidden once an estimate reaches Approved or Superseded.

Draft → Reviewed

  1. Click Advance on a Draft estimate.
  2. A Mark as Reviewed modal opens. Select one or more people in Reviewed By — this is required.
  3. Click Confirm. The estimate moves to Reviewed.

Reviewed → Shared

  1. Click Advance on a Reviewed estimate.
  2. No additional input is needed. The estimate moves to Shared immediately.

Shared → Approved

  1. Click Advance on a Shared estimate.
  2. If the project already has a project code set, the estimate is approved immediately — no further input needed.
  3. If the project does not yet have a project code, an Approve Estimate modal opens. Enter the project code (e.g. a Jira ID or portfolio reference). This is required before approval can proceed.
  4. Click Approve. The estimate moves to Approved. Any previously Approved estimate on this project is automatically moved to Superseded.
Approved and Superseded estimates are locked. Once an estimate reaches Approved or Superseded, it cannot be edited or deleted. This protects the record of what was agreed.

Approving via the Edit drawer

You can also change an estimate's status directly in the Edit drawer using the Status dropdown. If you set Status to Approved and the project has no project code, the Approve Estimate modal will open to collect the code before saving. Setting status to Reviewed, Shared, or Approved requires at least one reviewer in the Reviewed By field.

Approve and supersede

Only one estimate per project can be Approved at a time. When you approve a new version, the system automatically:

  • Sets the new estimate to Approved.
  • Sets any previously Approved estimate to Superseded.
  • Records a Superseded history entry on the old estimate with the note: "Superseded by a newer approved estimate."

Superseded estimates are kept permanently — they are never deleted automatically. They remain visible in the Estimates tab with a Superseded badge.

Deleting an estimate

Draft and Reviewed estimates can be deleted. Approved and Superseded estimates cannot be deleted.

  1. Click the Delete action on a Draft or Reviewed estimate.
  2. A confirmation modal opens. Type the version label (e.g. v2) to confirm.
  3. Click Delete. The estimate is permanently removed.

Version history panel

Every estimate maintains a full, read-only change log. To view it:

  1. Navigate to the Estimates tab.
  2. In the Version History panel, select a version from the picker.
  3. The history list shows every action on that estimate: Created, Updated, Approved, or Superseded — with the status transition, timestamp, and actor email.

History entries cannot be edited or deleted.

Email action

Once an estimate is Approved, an Email action appears on its row. Use it to trigger an approval notification email to stakeholders. After the first send the button changes to Resend Email — you can resend as many times as needed.

Exporting estimates

Click the Export button in the Estimates tab header to download estimate data. Choose from CSV, Excel (XLSX), PDF, or JSON. The export includes all estimate versions for the project and respects any active status filter.

Default export columns: Code, Project, Version, Status, Estimate Days, Contingency %, Day Rate (£), Total Cost (£), Active, Created On. Additional columns (Estimate Link, Approval Email Sent, Created By, Updated On, Updated By) can be selected from the export configuration panel.

Project size bands

The Size badge on each estimate is derived from its total cost against configurable thresholds. See Project Sizes for the full configuration guide and default values.

Common errors
"Shared By is required" — at least one person must be selected in Shared By before an estimate can be created.

"Please select at least one reviewer" — advancing to Reviewed requires at least one person in the Reviewed By field. Open the Mark as Reviewed modal and add a reviewer.

"Project code is required before approving" — the project does not yet have a project code. The Approve Estimate modal will ask for one. Enter the portfolio or finance reference code and confirm.

"Approved and superseded estimates cannot be edited" — the estimate is locked. To make changes, create a new estimate version, revise it, and advance it through the workflow.

"Invalid estimate link — must be a valid URL" — the Estimate Link field only accepts full URLs (e.g. https://). Remove the link or correct the format.
Tip: Create a new estimate version for every significant scope change — do not overwrite an existing one. Having the full version history (v1 scoping, v2 revised scope, v3 final approved) makes it easy to explain cost movements to stakeholders at any later date.

Sprint Forecast

Import planned effort per team into a sprint and confirm the data to drive recharge records for financial reconciliation.

Sprint Forecast captures the planned effort per story or ticket for a sprint — per team, per project label. Once each team's forecast is confirmed, the Review Complete action generates recharge detail records that feed the financial recharge process. These records group effort by project and recharge type, ready for billing or cost recovery.

Navigating to Sprint Forecast

  1. Go to Sprints and open the sprint you want to forecast.
  2. Click the Forecast button in the sprint detail page actions.
  3. The Sprint Forecast page shows a Teams panel with one accordion row per active team.

Team accordion

Each active team has an accordion row showing its name, a status badge for its latest import, and an Import button. Expand the accordion to see the full import history for that team.

Status badgeColourMeaning
Active BLUE The most recent import is in progress — uploaded but not yet confirmed.
Confirmed GREEN The import has been reviewed and confirmed. Rows are locked and included in recharge generation.
Superseded GREY An older import replaced when a newer file was uploaded for this team.

Uploading forecast data

  1. Click Download Template to get the CSV. Fill in one row per planned story or ticket.
  2. In the Teams panel, locate the team whose forecast you are uploading.
  3. Click Import on that team's accordion row.
  4. Select the completed CSV file. The file is uploaded immediately.
  5. A success toast confirms the upload and the team's status badge updates to Active.
Upload permissions. The Import button is only shown to users with the sprints.import_forecast permission.

Confirming an import

  1. Run Review and fix any failing rows, or decide to proceed despite failures.
  2. Click Confirm.
  3. If all checks passed, a confirmation drawer appears — click Confirm to lock the import.
  4. If checks failed, an Override Notes field appears. Enter a reason and click Confirm.
  5. The import status changes to Confirmed. If a newer version was already confirmed, this version supersedes it.
Confirming is irreversible. Once confirmed, a forecast import is locked. Upload a new file to make corrections — the previous version becomes Superseded.

Review Complete

Once all teams have confirmed their imports, click Review Complete to finalise the sprint forecast and generate recharge records.

  1. Click Review Complete in the page actions. The button requires the sprints.review_complete permission.
  2. A drawer opens showing the status of each team — which teams are confirmed and which are not.
  3. If all teams are confirmed, click Complete to proceed.
  4. If some teams are not yet confirmed, enable the Override checkbox, enter a note explaining why, and click Complete.
  5. The system generates recharge detail records from all confirmed rows across all teams for this sprint. A success message shows how many records were created.

What happens after Review Complete

Clicking Review Complete triggers the following:

  1. Recharge detail records are rebuilt — all existing forecast recharge detail records for this sprint are deleted and recreated from the latest confirmed import rows. Each row that has a valid assignee, label, and mapping creates one recharge detail entry.
  2. Cost is calculated — total cost per row is derived from the effort (in days) multiplied by the configured sprint point price. The hours-per-day setting converts effort seconds to days.
  3. Recharge aggregates are rebuilt — the system groups recharge detail records by project, programme, and recharge type, then creates or replaces aggregate recharge records. These aggregate records are what financial teams use for cost recovery and billing.
  4. Finance contacts are linked — for project-linked recharges, the project's finance and project contacts are automatically associated with the aggregate record.
Re-running Review Complete. You can click Review Complete again after uploading and confirming a corrected import. Each run fully rebuilds the recharge records for this sprint — previous recharge data is replaced, not accumulated.

Recharge records generated

The recharge workflow produces two levels of records:

Record typeDescription
Recharge Detail One record per confirmed import row. Stores the individual story-level effort, cost, assignee, project label, and recharge type. Used for granular audit and drill-down.
Recharge (aggregate) One record per unique combination of sprint, recharge type, programme, and project. Stores the summed total days and total cost. These are the financial-facing records used for billing and cost recovery.

Common issues
"Import button is not visible" — you need the sprints.import_forecast permission. Contact your administrator.

"Review Complete button is not visible" — this button requires the sprints.review_complete permission.

"Assignee check fails for a valid member" — the name in the CSV does not match the system. Check the member's display name or email in the Workforce section.

"Mapping check fails" — the recharge type code in the CSV is not mapped to the project type of the target label. Review the Recharge Types configuration and ensure the mapping exists.

"Zero recharge records created after Review Complete" — no teams had a confirmed import at the time Review Complete was triggered. Confirm at least one team's import before running Review Complete.
Tip: Run Review before confirming even if you expect all rows to pass — it surfaces mapping and label issues early. If corrections are needed, upload a new version of the file rather than editing individual rows.

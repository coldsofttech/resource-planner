Sprint Actuals

Import what each team actually delivered in a sprint and confirm the data for project cost tracking.

Sprint Actuals capture the real effort recorded against each story or ticket in a sprint — per team, per project label. Once confirmed, these figures flow into project-level cost totals on the Project Actuals tab and feed recharge detail records for financial reconciliation.

Navigating to Sprint Actuals

  1. Go to Sprints and open the sprint you want to record actuals for.
  2. Click the Actuals button in the sprint detail page actions.
  3. The Sprint Actuals page shows a Teams panel with one accordion row per active team.
Actuals cannot be imported for closed sprints. Once a sprint is closed its actuals page shows a locked state. Record and confirm actuals before closing the sprint.

Team accordion

Each active team has an accordion row showing its name, a status badge for its latest import, and an Import button. Expand the accordion to see the full import history for that team.

Status badgeColourMeaning
Active BLUE The most recent import is in progress — it has been uploaded but not yet confirmed.
Confirmed GREEN The import has been reviewed and confirmed. Data is locked and feeds project cost totals.
Superseded GREY An older import that was replaced when a newer file was uploaded.

Uploading actuals data

  1. Click Download Template to get the CSV template. Fill in one row per story or ticket.
  2. In the Teams panel, find the team whose data you are uploading.
  3. Click Import on that team's accordion row.
  4. Select the completed CSV file. The file is uploaded immediately — no confirmation step.
  5. A success toast appears and the import history table refreshes. The team's status badge updates to Active.
Upload permissions. The Import button is only shown to users with the sprints.import_actuals permission. Users without this permission can still view the import history table but cannot upload files.

Expanding a team accordion shows a table of all imports for that team in this sprint.

Import detail page

The import detail page shows the full contents of a single import version and lets you review, correct, and confirm it.

Rows tab

The Rows tab lists every row from the uploaded CSV. Each row represents one story or ticket.

ColumnDescription

TitleStory or ticket title.

Review checks

Clicking Review validates every row against four check types. Failing cells are highlighted in red in the Checks column.

CheckWhat it validates
AssigneeThe assignee name resolves to an active member in the system.
SprintThe sprint name resolves to an active sprint in the system.
LabelThe label exists as a project label in the system.
MappingThe recharge type mapping is valid for the project type linked to this label.

Use the Check Type filter above the table to view only rows with a specific failing check.

ColumnDescription

Adding, editing, and deleting rows

  • Add Row — click the button in the page actions to manually enter a story. Fill in Story Type, Jira ID, Title, Assignee, Efforts, Sprint, Label, and Mapping in the drawer and click Add Row.
  • Edit — click the Edit action on any row to open the edit drawer and update its fields. Re-run review after editing to refresh check results.
  • Delete — click the Delete action and confirm. Deleted rows are permanent — they cannot be restored.
CSV rows vs manual rows. Rows uploaded from a CSV file and rows added manually behave identically — both are reviewed and confirmed together.

Confirming an import

  1. Run Review and fix any failing rows (or decide to proceed despite failures).
  2. Click Confirm.
  3. If all checks passed, a confirmation drawer appears asking you to confirm the action.
  4. If any checks failed, an Override Notes field appears. Enter a reason for confirming despite the failures.
  5. Click Confirm in the drawer. The import status changes to Confirmed and the data is locked.
Confirming is irreversible. Once an import is confirmed it cannot be edited or deleted. If corrections are needed, upload a new version of the file — the old import becomes Superseded and the new one becomes the Active version to review and confirm.

Review Complete

Once all teams have confirmed imports, click Review Complete in the page actions to mark the sprint actuals as finalised.

  1. Click Review Complete. The button is only enabled when at least one team has a confirmed import.
  2. A drawer opens showing which teams (if any) do not yet have a confirmed import.
  3. If all teams are confirmed, a green success message is shown. Click Complete.
  4. If some teams are not confirmed, enable the Override checkbox to acknowledge this, then enter a note explaining why, and click Complete.

Sync Project Actuals

After review is complete, the Sync Project Actuals button becomes active (visible to users with sprints.review_complete permission). Syncing pushes confirmed actuals into project-level cost records, which then appear on each project's Actuals tab.

Wait before syncing. It is generally recommended to wait at least 3–5 days after Review Complete before syncing project actuals. This allows any late corrections to be uploaded and confirmed before the data is pushed to project records.
  1. Click Sync Project Actuals.
  2. Choose the scope — All Projects or Specific Projects.
  3. Click Sync. Project cost records are created or updated for all matching projects.

Recharge integration

Confirmed actuals also feed into the recharge workflow. Each confirmed row that has a valid mapping creates or updates a recharge detail record for the relevant project and sprint, ready for financial reconciliation. See the recharge documentation for how these records are managed downstream.

Common issues
"Import button is not visible" — you need the sprints.import_actuals permission. Contact your administrator to request access.

"Actuals page shows 'Sprint is closed'" — the sprint has been closed. Actuals must be uploaded and confirmed before closing a sprint.

"Review Complete button stays disabled" — at least one team must have a confirmed import for the button to become active. Confirm at least one team's import first.

"Assignee check fails for a valid team member" — the name in the CSV does not match the member's name in the system. Check the member's profile for the correct display name or email and update the CSV row accordingly.
Tip: Run Review before uploading a corrected file. If the only failures are mapping issues that are being handled separately, use the Override Notes field to document the reason and confirm anyway — this keeps the process moving without blocking other teams.

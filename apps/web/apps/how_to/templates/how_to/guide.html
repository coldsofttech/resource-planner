User Guide

This guide covers every module in Resource Planner — what it does, how to use it, and how each module connects to the others. No technical knowledge required.

Plan

Define financial years and sprints to structure delivery capacity over time.

Deliver

Track projects, estimates, budgets, and collaborators across programmes.

Manage

Organise teams, track capacity, and manage workforce skills and leaves.

Key Concepts

Understanding these concepts will make every other module easier to follow.

Codes

Every record in Resource Planner has an auto-generated code (e.g. TEAM-0001, PRJ-0042). Codes are permanent identifiers — they never change even if the record's name changes. You'll see them in URLs, exports, and API responses.

Active / Inactive

Most records have an is_active flag. Deactivating a record hides it from dropdowns and filters but keeps it in history. You can reactivate at any time. Deactivation is preferred over deletion to preserve audit trails.

Audit trail

Every record tracks who created and last modified it, and when. Key modules (Teams, Projects, Estimates) also maintain detailed history logs showing every change over time.

Defaults

Roles, Locations, and Employment Types each support a single default record. The default is pre-selected when creating new members, reducing data entry effort.

Import & Export

Most list pages support bulk import (CSV/XLSX) and export (CSV, XLSX, PDF, JSON). Import validates every row and reports errors before committing. Exports respect the current filter state — export only what you are looking at.

Financial Years

Define the fiscal periods that frame all planning, sprints, and budgets.

A Financial Year (FY) is the top-level planning container. Sprints live inside FYs, project budgets are allocated per FY, and reporting is always anchored to an FY. Resource Planner automatically labels each FY in long form (FY2024-2025) and short form (FY24-25).

Fields

FieldDescription
start_dateFirst day of the financial year.
end_dateLast day of the financial year.
statusFuture — not yet started. In Progress — the current active FY. Completed — finished normally. Expired — ended without being marked completed.
long_fy / short_fyAuto-generated labels derived from start/end dates.
span_daysTotal calendar days — calculated automatically.
noteOptional free-text note.
is_activeWhether this FY appears in dropdowns and filters.

How to use

  1. Go to Financial Years from the navigation menu.
  2. Click Add Financial Year and enter the start and end dates.
  3. Set the status to Future if the year has not started yet, or In Progress if it is the current year.
  4. Save. The long/short labels and span are calculated for you.
Only one "In Progress" FY allowed at a time. When you set a new FY to In Progress, the previously active FY is automatically moved to Completed. Date ranges must not overlap between financial years.
Tip: Create the next FY in Future status before the current one ends. Transition it to In Progress on day one of the new year to trigger the automatic completion of the previous FY.

Sprints

Time-boxed delivery periods within a Financial Year, with per-member capacity tracking.

Sprints divide a Financial Year into delivery windows. Each sprint tracks the available capacity of every team member — how many days they can work after subtracting holidays and approved leaves.

Fields

FieldDescription
financial_yearThe FY this sprint belongs to.
sprint_numberUnique sprint number across all FYs (e.g. 24, 25, 26…).
nameDisplay label, e.g. S24.10.
start_date / end_dateThe sprint window.
monthAuto-derived from end date (YYYY-MM).
statusFuture / In Progress / Completed / Expired — mirrors FY status logic.
is_closedWhen closed, the sprint is locked — no further edits to capacity.
noteOptional free-text note.

Capacity

Each sprint automatically calculates per-member capacity:

FieldMeaning
working_daysTotal calendar days in the sprint window.
holiday_daysPublic holidays in the member's location during the sprint.
leave_daysApproved leave days falling within the sprint.
net_capacityworking_days − holiday_days − leave_days = actual available days.

How to use

  1. Navigate to Sprints and select a Financial Year.
  2. Click Add Sprint, enter the sprint number, name, and date range.
  3. Capacity is calculated automatically once holidays and leaves are recorded for the period.
  4. Open a sprint to view its capacity breakdown per team member.
  5. When the sprint period is over, click Close Sprint to lock it.
Closed sprints are locked. Once a sprint is closed, its capacity figures cannot be changed. Close sprints only after all leaves for the period have been finalised.

Projects

The core delivery entity — tracks status, estimates, budgets, collaborators, and history.

A Project represents a funded body of work. It links to a Programme, is owned by a Team, progresses through configurable statuses, accumulates versioned estimates, and receives a per-FY budget allocation.

Core project fields

FieldDescription
nameUnique project name (used as the canonical identifier).
display_nameShorter name for dashboards and reports.
programmeThe programme this project belongs to.
project_typeClassification (e.g. "Transformation", "Run & Maintain").
status / sub_statusCurrent lifecycle position. Sub-statuses are children of a main status.
assigned_teamThe primary delivery team.
confidenceLow / Medium / High / Very High — delivery confidence level.
priorityLow / Medium / High / Very High — business priority.
start_date / end_datePlanned delivery window.
commitment_dateDate committed to stakeholders.
efforts_issuedWhether a Purchase Order or effort authorisation has been issued.
run_cost_appliesIndicates ongoing run costs apply after delivery.
tagsFlexible labels from the Tag library.

Project Codes

Each project can have a project code — an external reference number (e.g. a Jira ID, portfolio number, or finance code). Only one code is active per project at a time. Every code change is recorded in the Code History log with a timestamp and the actor who made the change.

Estimates

Projects accumulate versioned estimates (v1, v2, v3…). Each estimate records:

FieldDescription
estimate_daysTotal effort in person-days.
day_rateCost per person-day.
contingency_percentageContingency buffer as a percentage.
total_costAuto-calculated: (days × rate) + contingency.
statusDraft → Reviewed → Shared → Approved → Superseded.
reviewed_by / shared_byUsers who reviewed or received the estimate.
estimate_linkURL to the detailed estimate document.
Estimate workflow: Draft → created, being refined. Reviewed → reviewed internally. Shared → sent to stakeholders. Approved → formally signed off. Superseded → replaced by a newer version. When a new estimate version is created, the previous version is automatically marked Superseded.

Budgets

A budget is allocated per project per Financial Year. Each budget entry links to a specific estimate version and records:

  • Allocated budget — the initial approved amount.
  • Refined budget — an updated figure (overrides allocated when set).
  • Actual budget — whichever of the above is current.
  • Remaining budget — actual budget minus the linked estimate's total cost.

Collaborators

Teams other than the primary assigned_team can be added as collaborators. Collaborator teams contribute capacity and effort to the project but are not the lead team.

Labels

Projects support custom labels — short internal identifiers (max 50 chars) specific to that project. One label per project can be marked as default. Labels are distinct from Tags (which come from the shared tag library).

How to use

  1. Navigate to Projects and click Add Project.
  2. Fill in the name, programme, type, status, assigned team, dates, and priority.
  3. Once created, open the project to add an estimate (start with Draft).
  4. Progress the estimate through the workflow as it is reviewed and approved.
  5. Allocate a budget for the current Financial Year, linking it to the approved estimate.
  6. Add collaborator teams and tags as needed.
  7. Update the status as the project progresses through delivery.
Tip: Use the Followers feature to subscribe relevant stakeholders. Followers receive notifications when the project status or estimate changes.

Programmes

Group related projects under a strategic initiative or delivery programme.

A Programme is a named grouping for related projects. Reporting and portfolio views can roll up budgets and delivery status across all projects within a programme.

FieldDescription
nameUnique programme name.
descriptionOptional longer description.
is_activeControls availability in project dropdowns.
is_protectedProtected programmes cannot be deleted, only deactivated.

How to use

  1. Navigate to Projects → Programmes.
  2. Click Add Programme, enter a name and description, and save.
  3. When creating or editing projects, select the programme from the dropdown.
Tip: Create programmes before creating projects. A project must belong to a programme — you cannot assign a project to "no programme".

Teams

Organise your workforce into delivery teams and manage team membership.

Teams are the core organisational unit for resource allocation. Members are assigned to teams, and projects are owned and collaborated on by teams. Every team assignment is recorded in an immutable history log.

Team fields

FieldDescription
nameUnique team name (max 120 characters).
descriptionOptional description of the team's purpose.
is_activeInactive teams are hidden from assignment dropdowns.

Assignments

A team is made up of members. The assignment rules differ by role:

  • Regular members — can only belong to one team at a time. Assigning them to a new team removes them from their current team and records the move in history.
  • Leadership members (role marked is_leadership=true) — can belong to multiple teams simultaneously.

Assignment History

Every team change is recorded: which member moved, from which team, to which team, when, and who made the change. This history is immutable — it cannot be edited or deleted.

How to use

  1. Go to Teams and click Add Team. Enter a name and description.
  2. Open the team's detail page to view its current members.
  3. To assign a member, open the member's profile and set their team — or use the team's assignment panel.
  4. To move a member between teams, update their team assignment. The system records the transfer automatically.
Tip: Use the Team detail page to see the full history of who has been on the team, when they joined, and when they left. This is invaluable for retrospectives and capacity planning.

Members

Workforce profiles — personal details, skills, role, employment type, and preferences.

Every user in Resource Planner has a Profile that combines their account details with workforce data. Admins manage workforce fields; users manage their own personal preferences.

Profile fields

FieldWho can editDescription
display_nameUserPreferred display name (overrides first/last name in the UI).
themeUserLight, Dark, or System — persisted per user.
timezoneUserUser's local timezone.
roleAdminJob role from the Roles library.
skillsAdminSkills from the Skills library (multi-select).
locationAdminOffice location — used for holiday calculations.
employment_typeAdminEmployment type (full-time, part-time, etc.).
joined_dateAdminWhen the member joined.
leaving_dateAdminWhen the member is scheduled to leave (optional).

Groups & Permissions

Users are assigned to one or more Groups. Each group has a set of permissions that control which modules and actions a member can access. Groups marked is_admin_group grant full access. Groups marked is_system are managed by the platform and cannot be deleted.

How to use

  1. Go to Members to see the full workforce list.
  2. Click a member to open their profile. Workforce fields are in the Workforce tab.
  3. To update role, skills, location, or employment type, you need the change_user_workforce permission.
  4. Members can update their own display name, theme, and timezone from Profile in the top-right menu.
  5. To invite a new user, go to Users (admin area) and create an account.
Tip: Always set a member's location before recording their leaves. The leave day calculator uses the member's location to look up public holidays, so an incorrect or missing location will produce wrong capacity figures.

Leaves

Record employee leave requests and automatically adjust sprint capacity.

Leave records represent approved absence periods. When a leave is saved, Resource Planner calculates the exact number of working days lost (excluding public holidays in the member's location) and reflects this in sprint capacity calculations.

Fields

FieldDescription
memberThe team member taking leave.
start_date / end_dateThe leave period. For half-days, start and end must be the same date.
is_half_dayWhether this is a half-day leave.
half_day_periodAM or PM — only applicable when is_half_day is true.
daysAuto-calculated: working days in the range minus public holidays at the member's location.
noteOptional reason or notes.

How to use

  1. Go to Leaves and click Add Leave.
  2. Select the member and enter the start and end dates.
  3. If it is a half-day, toggle the Half Day switch and select AM or PM.
  4. Save. The days field is calculated automatically.
  5. Sprint capacity for any sprints that overlap the leave period is updated immediately.
Overlapping leaves are blocked. You cannot create two leave records for the same member on the same dates. If you need to modify a leave period, edit the existing record rather than creating a new one.
Tip: Record leaves before closing the relevant sprint. Closing a sprint locks its capacity figures — leaves added after close will not update the capacity of closed sprints.

Business Units

Represent the organisational divisions that own teams and budget.

Business Units are top-level organisational groupings — divisions, departments, or cost centres. Teams and budget allocations can be associated with a business unit for reporting and portfolio views.

FieldDescription
nameUnique full name of the business unit (max 255 characters).
short_nameAbbreviated name for dashboards and badges (max 10 characters).
is_activeControls availability in dropdowns and reports.

How to use

  1. Go to Business Units and click Add Business Unit.
  2. Enter the full name and a short abbreviation (e.g. Finance / FIN).
  3. Save. Business units then appear in team and reporting dropdowns.

Roles

Job roles that define seniority, team assignment rules, and resource planning filters.

Roles classify what a team member does. Two flags on a role have functional consequences beyond just labelling.

FieldDescription
roleUnique role name (max 100 characters), e.g. "Senior Engineer", "Delivery Manager".
is_leadershipIf true, members with this role can be assigned to multiple teams simultaneously.
is_assignableIf true, members with this role can be allocated to projects in resource plans.
is_defaultPre-selected when creating new members. Only one role can be default.
is_activeInactive roles are hidden from member profile dropdowns.
is_leadership affects team assignment. Changing a member's role from non-leadership to leadership (or vice versa) does not automatically update their team assignments. Review team memberships after changing this flag.

How to use

  1. Go to Roles and click Add Role.
  2. Enter the role name and set the is_leadership and is_assignable flags appropriately.
  3. Mark one role as default — this will be pre-selected for new members.

Skills

A shared taxonomy of competencies assigned to team members for resource matching.

Skills define the competencies in your workforce. Members can hold multiple skills. Resource planning and workforce reports can filter by skill to find available capacity with specific expertise.

FieldDescription
skillUnique skill name (max 20 characters), e.g. "Python", "AWS", "Agile".
descriptionOptional explanation of what the skill covers.
is_activeInactive skills are hidden from member profile dropdowns but remain on existing profiles.

How to use

  1. Go to Skills and click Add Skill.
  2. Enter a short, precise name (max 20 chars) — e.g. Python not Python programming language.
  3. Add an optional description and save.
  4. Assign skills to members via their Profile → Workforce tab.
Tip: Keep the skill list concise and well-defined. A large, poorly-organised skill taxonomy becomes hard to maintain and reduces the usefulness of skill-based filtering.

Employment Types

Classify how team members are engaged — permanent, contractor, part-time, etc.

Employment Types label the nature of each member's engagement. They are used in workforce reporting and filtering, and can influence capacity assumptions for different member categories.

FieldDescription
nameUnique name (max 100 chars), e.g. "Full-time Permanent", "Fixed-Term Contractor".
is_defaultPre-selected when creating new members. Only one can be default.
is_activeInactive types are hidden from member profile dropdowns.

How to use

  1. Go to Employment Types and click Add Employment Type.
  2. Enter a clear name and mark one as the default (typically "Full-time Permanent").
  3. Employment type is then selectable on each member's workforce profile.

Locations

Office locations that anchor public holidays and default working calendars.

Locations are city/country pairs. A member's location determines which public holidays apply when calculating their leave days and sprint capacity. Getting this right is important for accurate capacity planning.

FieldDescription
cityCity name (max 100 chars).
countryCountry name (max 100 chars).
is_defaultPre-selected when creating new members. Only one location can be default.
is_activeInactive locations are hidden from member profile dropdowns.
City + Country must be unique. You cannot create two locations with the same city and country. If you have multiple offices in the same city, differentiate them (e.g. "London - East" / "London - West") or add them under the same location.

How to use

  1. Go to Locations and click Add Location.
  2. Enter the city and country. Mark one as the default.
  3. Make sure to add Holidays for each location (see below) before leaves are recorded for members in that location.

Holidays

Public holidays per location — used to calculate working days in leaves and sprint capacity.

Holidays are per-location, per-date records. They are used by the leave day calculator and sprint capacity engine to exclude non-working days from capacity figures.

FieldDescription
nameHoliday name (max 120 chars), e.g. "Christmas Day".
dateThe date of the holiday.
locationThe location this holiday applies to.
One holiday per date per location. Each (location, date) combination must be unique. If a country has a single bank holiday that applies to multiple city locations, you must add it separately for each location.

How to use

  1. Go to Holidays and click Add Holiday.
  2. Select the location, enter the date and holiday name, and save.
  3. Repeat for each location that observes that holiday.
  4. Use the Import feature to bulk-load a year's holidays from a CSV file.
Tip: Add the full year's public holidays for each location at the start of every Financial Year — before any sprints or leaves are recorded. This ensures all capacity figures are accurate from the start.

Tags

Flexible labels for cross-cutting categorisation of projects and other entities.

Tags are simple name-only labels from a shared library that can be applied to projects. Unlike a project's own Labels (which are project-specific), Tags are reusable across all projects and enable cross-portfolio filtering and reporting.

FieldDescription
nameUnique tag name (max 50 chars), e.g. "cloud-migration", "regulatory", "high-risk".

How to use

  1. Go to Tags and click Add Tag. Enter a concise name and save.
  2. Assign tags to projects via the project's Tags field.
  3. Use tag filters in the Projects list to find all projects with a given tag.
Tip: Tags work best when used consistently. Agree on a tag vocabulary with your team before creating tags — having both "cloud" and "cloud-migration" and "Cloud Migration" reduces their filtering value.

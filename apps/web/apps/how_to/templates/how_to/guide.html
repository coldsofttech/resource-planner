User Guide

Step-by-step instructions for every module in Resource Planner. Start with Key Concepts to understand the building blocks, then jump to the module you need.

Plan

Set up financial years and sprints to frame delivery capacity over time.

Deliver

Create and manage projects, estimates, budgets, and programmes.

Manage

Organise teams, track capacity, and manage workforce skills and leaves.

Key Concepts

Understand these ideas once and everything else will make sense.

Codes

Every record gets an auto-generated code when it is created — for example TEAM-0001 or PRJ-0042. Codes are permanent: they never change even if you rename the record. You will see them in search results, exports, history logs, and URLs.

Active and Inactive

Most records can be set to Active or Inactive. Inactive records disappear from dropdown menus and filters so they do not clutter your day-to-day view — but they are not deleted. You can reactivate them at any time. Use inactive to archive records you no longer need without losing their history.

Audit trail

Every record shows who created it and when it was last changed. Key modules (Teams, Projects, Estimates) also keep a full change history — a timestamped log of every edit, who made it, and what the previous value was. History logs are read-only and cannot be altered.

Defaults

Roles, Locations, and Employment Types each support a single default record. When you create a new team member, the default values are pre-filled for you. Only one record per type can be the default at any time — setting a new default automatically clears the previous one.

Filters

Every list page has a filter bar. Use it to narrow down what you are looking at before taking an action. Filters also affect exports — if you apply a filter and then export, only the filtered records are downloaded. Remove all filters first if you want the full list.

Importing records

Most list pages have an Import button. Use it to create many records at once from a spreadsheet.

  1. Click Import on the list page.
  2. Download the sample template — it shows the exact columns and format required.
  3. Fill in your data and save the file as CSV or XLSX.
  4. Upload the file. The system validates every row and shows a preview with any errors before saving anything.
  5. Fix any highlighted errors and re-upload. When there are no errors, click Confirm Import to commit.
Tip: Always download a fresh sample template for each import — it reflects the current column requirements exactly. Using an old template from a previous session may cause format errors.

Exporting records

Click Export on any list page to download the visible records. Choose from CSV, Excel (XLSX), PDF, or JSON. The export respects your current filters — only matching records are included.

Supported export formats
CSV — plain text, opens in any spreadsheet app.
XLSX — formatted Excel workbook with column headers.
PDF — ready-to-print document.
JSON — structured data for integrations or backups.

Financial Years

The top-level planning container for sprints, budgets, and all reporting.

A Financial Year (FY) is the foundation of everything in Resource Planner. Sprints sit inside FYs, project budgets are allocated per FY, and all reports are anchored to a financial year. Set these up first, before creating sprints or allocating budgets.

Actions on this page

Button / ActionWhat it does
Add Financial YearOpens a panel on the right. Enter the start date, end date, initial status, and an optional note. Labels and duration are calculated for you.
View Opens a read-only summary of the financial year, including all sprints within it.
Edit Update the dates, status, or note.
Deactivate / ActivateHides or shows the FY in planning dropdowns. Does not affect existing sprints or budget data.

Status explained

StatusWhen to use it
FutureThe year has not started. Use when creating an upcoming FY in advance.
In ProgressThe currently active year. Only one FY can be In Progress at a time.
CompletedThe year ended normally. Sprints and budgets are preserved for historical reporting.
ExpiredThe end date passed without the year being marked Completed.

Setting up a financial year

  1. Go to Financial Years in the navigation.
  2. Click Add Financial Year.
  3. Enter the start date (e.g. 1 July) and end date (e.g. 30 June the following year).
  4. Set the status to Future if it has not started yet, or In Progress for the current year.
  5. Click Save. The year label (e.g. FY2025-26) and total days are calculated automatically.

Transitioning to a new year

  1. Create the new FY with status Future a few weeks before the current year ends.
  2. On the first day of the new year, open it and change the status to In Progress.
  3. The current FY is automatically moved to Completed — you do not need to update it manually.
Only one year can be In Progress at a time. Setting a second FY to In Progress will be blocked if another one is already active. Transition or complete the current year first.
Common errors
"Date ranges overlap with an existing financial year" — your new FY's start or end date falls inside an existing one. Ensure the years sit end-to-end with no overlap. A common mistake: if the current year ends on 30 June, the new one should start on 1 July, not 30 June.
Tip: Create the next FY in Future status a few weeks early. This lets you set up sprints and start planning for the upcoming year before the current one closes.

Sprints

Time-boxed delivery windows within a Financial Year, with automatic capacity tracking per member.

Sprints divide a Financial Year into delivery windows — typically fortnightly or monthly. Each sprint automatically calculates how many days each team member is available, subtracting public holidays and approved leave from the calendar days in the window.

Actions on this page

Button / ActionWhat it does
Add SprintOpens a panel. Select a financial year, enter a sprint number, name, date range, and status.
View Opens the sprint detail — shows the capacity breakdown for every team member: working days, holidays, leave, and net available days.
Edit Update dates, status, or notes. Capacity is recalculated on save.
Close SprintLocks the sprint permanently. Capacity figures cannot change after closing. Use once the sprint period has ended and all leaves for that period are recorded.

How capacity is calculated

FigureHow it is worked out
Working daysTotal calendar days in the sprint window (weekends included — the system uses a full calendar day count).
HolidaysPublic holidays in the member's location that fall within the sprint dates.
Leave daysApproved leave records for this member that overlap the sprint.
Net capacityWorking days minus holidays minus leave — the actual days available for project allocation.

Creating a sprint

  1. Go to Sprints and click Add Sprint.
  2. Select the Financial Year this sprint belongs to.
  3. Enter a sprint number (unique across all years), a display name, and the start and end dates.
  4. Set the status to Future or In Progress.
  5. Click Save. Capacity is calculated automatically for all members.

Closing a sprint

  1. Make sure all leaves for the sprint period are recorded.
  2. Open the sprint and click Close Sprint.
  3. Confirm the action. The sprint is now locked — capacity and status are frozen for historical reporting.
Record all leaves before closing. Once a sprint is closed, its capacity figures are frozen. Leaves added after closing only update open and future sprints — not the closed one.
Common errors
"Sprint dates must fall within the selected financial year" — the start or end date falls outside the FY window. Adjust the sprint dates or select the correct financial year.

"Sprint number already exists" — sprint numbers are unique across all financial years. Use the next available number in the sequence.

"Capacity shows zero holidays even though holidays are recorded" — the member likely has no location set on their profile. Go to the member's Workforce tab and set their location.
Tip: Open a sprint's detail view to see the full capacity table — including which members are at zero capacity (fully on leave) or have reduced capacity due to holidays. Use this before assigning work in a resource plan.

Projects

The core delivery entity — status, estimates, budgets, collaborators, and history in one place.

A Project captures everything about a funded body of work — what it is, who owns it, where it is in delivery, how much it costs, and who is involved. Every project belongs to a Programme, is owned by a Team, and can carry multiple estimate versions and a per-FY budget.

Actions on the projects list

Button / ActionWhat it does
Add ProjectOpens the creation panel. Fill in the name, programme, type, status, team, dates, and priority.
View Opens the full project detail page — overview, estimates, budget, collaborators, history, and followers tabs.
Edit Update the project's core fields (name, status, dates, team, priority, tags, etc.).
ExportDownload the project list in your chosen format. Current filters are respected.

Creating a project

  1. Go to Projects and click Add Project.
  2. Enter the full name and a short display name (used in dashboards and reports).
  3. Select a Programme — every project must belong to one.
  4. Choose the project type, current status, and the team responsible for delivery.
  5. Enter the planned start and end dates, a commitment date if known, and the business priority.
  6. Add any Tags to help with cross-programme filtering.
  7. Click Save. A unique project code is generated automatically.

Project statuses

Statuses represent your organisation's delivery lifecycle (for example: Scoping → In Progress → Completed). Sub-statuses sit underneath a main status for finer-grained tracking. Your administrator configures which statuses are available — contact them if you need a new one added.

Estimates

An estimate records how much effort and cost a project requires. You can hold multiple estimate versions as scope evolves — the most recent approved one is used in budget and financial views.

Adding and progressing an estimate

  1. Open the project and click the Estimates tab.
  2. Click Add Estimate. Enter the number of effort days, a day rate, and an optional contingency percentage. The total cost is calculated automatically.
  3. Add a link to your detailed estimate document if you have one, and save.
  4. The estimate starts in Draft. Move it forward through the workflow as it is reviewed and approved.
  5. When a new estimate version replaces an old one, the previous version is automatically marked Superseded and kept for reference.

Estimate workflow

StatusWhat it means
DraftBeing prepared — not yet shared externally.
ReviewedReviewed internally by the team.
SharedSent to the business or stakeholders for sign-off.
ApprovedFormally agreed. This version is used when creating a budget.
SupersededReplaced by a newer version. Kept for historical reference.

Budgets

A budget allocates funding to a project for a specific Financial Year. It links to an estimate version and tracks three figures:

  • Allocated budget — the initial approved funding amount.
  • Refined budget — an updated figure that overrides the allocated amount once a more accurate number is known.
  • Remaining budget — current budget minus the linked estimate total, giving instant over/under-spend visibility.

To add a budget: open the project, click the Budget tab, then Add Budget. Select the Financial Year and the estimate to link it to.

Collaborators

A project has one primary team that leads delivery. Other teams contributing can be added as Collaborators. Collaborating teams appear alongside the primary team in resource planning and capacity views.

To add a collaborator: open the project, go to the Collaborators tab, and click Add Collaborator. Select the team and their role on the project.

Project codes

A project code is an external reference — a Jira ID, portfolio number, or finance code. Only one code is active per project at a time. Every code change is stored in the Code History log with a timestamp and who made the change.

Labels

Labels are short project-specific identifiers (up to 50 characters) you define directly on the project — useful for internal reference numbers unique to that project. One label per project can be marked as the default. Labels are different from Tags: tags come from a shared library and work across all projects; labels belong only to this project.

Followers

Team members can follow a project to receive notifications when its status or estimate changes. Open the project and click Follow to subscribe yourself. Administrators can add followers on behalf of others from the Followers tab.

Common errors
"Programme is required" — every project must belong to a programme. Create the programme first if it does not exist yet (see Programmes).

"Project name already exists" — names must be unique across the system. Add a year, team abbreviation, or qualifier to differentiate it.

"Commitment date cannot be before the start date" — check both dates and ensure the commitment date is on or after the project start date.
Tip: Keep project statuses up to date. Stale statuses make portfolio views unreliable and erode leadership confidence in the data. If a status is genuinely unknown, use the closest available sub-status and add a note rather than leaving it out of date.

Programmes

Group related projects under a strategic initiative for portfolio-level reporting.

A Programme is a named container for related projects. Portfolio views and reports can roll up budget totals and delivery status across every project in a programme. Every project must belong to a programme — create programmes before creating projects.

Actions on this page

Button / ActionWhat it does
Add ProgrammeCreates a new programme. Enter a name and optional description.
Edit Update the programme name or description.
Deactivate / ActivateHides or shows the programme in the project creation dropdown. Does not affect existing projects.
Delete Permanently removes the programme. Only possible when no projects are linked to it.

How to use

  1. Go to Projects → Programmes.
  2. Click Add Programme, enter a name and optional description, and save.
  3. When creating a project, select this programme from the dropdown.
Protected programmes cannot be deleted. Some programmes are marked as protected by an administrator. They can only be deactivated, not deleted, to preserve historical project data.
Common errors
"Cannot delete a programme with linked projects" — reassign or delete all projects in this programme before deleting it. Consider deactivating instead of deleting if you want to keep the history.
Tip: Set up your programme structure before inviting other users. A project cannot be saved without a programme, so having them ready prevents blockages when the team starts adding projects.

Teams

Organise your workforce into delivery teams. Every membership change is recorded in history.

Teams are the central organising unit for resource allocation. Members belong to teams, and projects are owned and collaborated on by teams. Every team change — who joined, who left, when — is recorded in an immutable history log.

Actions on this page

Button / ActionWhat it does
Add TeamCreates a new team. Enter a name and optional description.
View Opens the team detail page — current members, assignment history, and projects this team owns or collaborates on.
Edit Update the team name or description.
Deactivate / ActivateHides or shows the team in assignment dropdowns. Existing member assignments and project links are not removed.
Delete Permanently removes the team. Only possible when no members are assigned and no projects reference the team.
ImportCreate multiple teams at once from a CSV or Excel file.
ExportDownload the full team list.

Creating a team

  1. Go to Teams and click Add Team.
  2. Enter a clear, unique team name and an optional description of the team's purpose.
  3. Click Save.
  4. Add members by opening each member's profile and updating their team assignment — or use the team's assignment panel inside the team detail page.

Team assignment rules

  • Regular members can only be on one team at a time. Moving someone to a new team automatically removes them from their current team and records the transfer in history.
  • Leadership members (those with a role marked as Leadership) can belong to multiple teams simultaneously. Assigning them to a second team does not remove them from the first.

Viewing team history

Open the team's detail page and click the History tab. You will see the complete log of who joined the team, when, who they replaced, and who made each change. This log is read-only — it cannot be edited or deleted.

Common errors
"Cannot delete a team with active members" — reassign all current members to other teams before deleting. To stop using the team without losing history, deactivate it instead of deleting.

"Cannot delete a team linked to projects" — remove the team from all projects (as primary team or collaborator) before attempting to delete it.
Tip: Use the team History tab for retrospectives and capacity reviews. It shows exactly who was on the team during any past sprint period — invaluable when revisiting what capacity was actually available.

Every user has a profile combining their account settings with workforce data. Some fields are controlled by administrators; others are managed by the members themselves from their own Profile menu.

Updating a member's workforce details

  1. Go to Members and click the member's name to open their profile.
  2. Click the Workforce tab.
  3. Click Edit and update the role, skills, location, employment type, and dates as needed.
  4. Click Save.

Inviting a new member

  1. Go to Users in the admin area.
  2. Click Invite User and enter their email address.
  3. Assign them to the appropriate permission group.
  4. Once they accept the invitation and sign in, open their profile and fill in the Workforce details — role, location, team, and employment type.
Always set the location before recording leaves. The leave day calculator uses the member's location to find public holidays. A missing or incorrect location means sprint capacity figures will be inaccurate for that member.
Common errors
"You do not have permission to edit workforce fields" — you need the workforce management permission. Contact your administrator to request access.

"Leaving date cannot be before joining date" — check both fields and ensure the leaving date is on or after the joining date.
Tip: Encourage members to set their own display name from the Profile menu. The display name appears throughout the platform and is more recognisable than a raw email address or first/last name combination.

Leaves

Record approved absences — sprint capacity is automatically adjusted.

Leave records represent approved absence periods. When you save a leave record, Resource Planner calculates the exact working days lost — excluding public holidays at the member's location — and immediately updates sprint capacity for any sprints that overlap the leave period.

Actions on this page

Button / ActionWhat it does
Add LeaveOpens a panel. Select the member, enter the dates, and choose whether it is a full day, half day AM, or half day PM.
Edit Update the leave dates or notes. Sprint capacity is recalculated on save.
Delete Removes the leave record and restores the capacity days to all open sprints that overlapped it.
ImportBulk-load leave records for multiple members at once from a CSV or Excel file — the fastest way to enter planned leave for a whole team.
ExportDownload the leave list with your current filters applied.

Recording a leave

  1. Go to Leaves and click Add Leave.
  2. Select the team member who is taking leave.
  3. Enter the start and end dates.
  4. If it is a half-day, enable the Half Day toggle and select AM or PM. For a half-day, start and end must be the same date.
  5. Click Save. Working days are calculated automatically. Any open sprint that overlaps these dates is updated immediately.

How days are counted

The system counts working days in the leave range and subtracts any public holidays at the member's location. A full day counts as 1; a half-day counts as 0.5. Weekends are counted as part of the calendar range but will not increase the day count beyond what the system considers working days based on your location's holiday data.

Record leaves before closing sprints. Closing a sprint locks its capacity figures. Leave records added after a sprint is closed will not update the closed sprint — only open sprints are recalculated.
Common errors
"Leave dates overlap with an existing leave record for this member" — this member already has leave covering some of these dates. Edit the existing record rather than creating a new one, or adjust the date range.

"Half-day start and end dates must be the same date" — for a half-day, both the start and end date must be identical.

"Capacity has not changed after adding leave" — the sprint may already be closed, or the member does not have a location set. Check both — a closed sprint's capacity is frozen; a member without a location will not have holidays correctly applied either.
Tip: At the start of each financial year, use Import to load the full year's planned leave for all team members in one go. This gets accurate capacity figures into every sprint before planning begins, and is far faster than entering leave one record at a time.

Roles

Define job roles that control multi-team assignment eligibility and resource plan visibility.

Roles classify what a team member does. Two flags on a role have real functional effects on how the platform behaves — not just how the member is labelled.

Actions on this page

Button / ActionWhat it does

Edit Update the name or flags. Changes apply immediately to all members who hold this role.

Import / ExportBulk-create roles from a spreadsheet, or download the list.

The two functional flags

FlagWhat it controls
Leadership Members with this flag can be assigned to multiple teams at the same time. Regular (non-leadership) members can only be on one team. Use this for managers, heads of practice, or anyone who spans multiple teams.
Assignable Members with this flag appear in the resource planning allocation panel. Non-assignable members (e.g. administrative staff) are excluded. Tick this for any role that does project delivery work.

How to use

  1. Go to Roles and click Add Role.
  2. Enter the role name (e.g. Senior Engineer, Delivery Manager).
  3. Enable Leadership if members with this role should be able to span multiple teams.
  4. Enable Assignable if members with this role should appear in resource planning.
  5. Mark one role as the default — it is pre-selected when creating new members.
  6. Click Save.
Changing Leadership affects existing team assignments. If you change a member's role from non-leadership to leadership (or vice versa), their team assignments are not automatically adjusted. Review the member's team memberships manually after changing this flag.
Common errors
"Cannot delete a role assigned to active members" — use the Export button to see which members hold this role, then reassign them before attempting to delete.

Skills

A shared library of competencies assigned to team members for resource matching.

Skills define the competencies in your workforce. Members can hold multiple skills. Skill data powers workforce search and resource planning filters — helping you find people with the right expertise for a given project.

How to use

  1. Go to Skills and click Add Skill.

Locations

Office locations that control which public holidays apply to each team member.

A member's location determines which public holidays are excluded from their leave day count and sprint capacity. Getting this right matters: an incorrect or missing location produces inaccurate capacity figures across all sprints and resource plans for that member.

Actions on this page

Button / ActionWhat it does
Add LocationCreate a city/country pair. After saving, go to Holidays to add the public holidays for this location.
Edit Update the city or country name.
Set as DefaultPre-selects this location when creating new members.
Deactivate / ActivateHides or shows the location in member profile dropdowns. Existing member assignments are preserved.
Delete Removes the location if no members are assigned to it.
Import / ExportBulk-create locations from a spreadsheet, or download the list.

How to use

  1. Go to Locations and click Add Location.
  2. Enter the city and country. Mark one location as the default.
  3. Click Save.
  4. Go to Holidays and add the public holidays for this location before any leaves or sprints use it.
  5. Assign the location to team members via their Profile → Workforce tab.

Tip: Set up locations and their holidays before inviting members or recording any leaves. Members without a location will have no public holidays deducted, which inflates their apparent capacity in every sprint.

Holidays

Public holidays per location — automatically excluded from leave day counts and sprint capacity.

Holiday records tell Resource Planner which dates are non-working days for each location. They are factored out of leave calculations and sprint capacity automatically. Without them, capacity is overstated for every member in a location that observes public holidays.

Actions on this page

Button / ActionWhat it does
Add HolidayRecord a single public holiday for a specific location and date. All open sprints and leaves that cover this date are recalculated immediately.
Edit Update the holiday name or date. Capacity is recalculated on save.
Delete Removes the holiday. Open sprints and leaves that covered this date are recalculated — the day is restored to capacity.
ImportBulk-load a full year's public holidays for one or more locations from a CSV or Excel file — by far the fastest way to set up holiday data.
ExportDownload the holiday list for your currently filtered location and date range.

Recording a single holiday

  1. Go to Holidays and click Add Holiday.
  2. Select the location this holiday applies to.
  3. Enter the date and the holiday name (e.g. Christmas Day).
  4. Click Save. All open sprints and leave records covering this date are updated immediately.

Bulk importing a full year's holidays

  1. Click Import on the Holidays page.
  2. Download the sample template. It shows three columns: location, date, and holiday name.
  3. Fill in every public holiday for each location. If the same bank holiday applies to multiple locations, add a row for each one.
  4. Upload the file. Review the preview and fix any errors.
  5. Click Confirm Import. Capacity figures across all affected sprints and leaves are recalculated immediately.
One record per location per date. Each location/date combination is unique. If the same bank holiday applies across multiple city locations, add it separately for each — one row per location in your import file.
Common errors
"A holiday already exists for this location on this date" — check whether the holiday is already recorded before adding it again. Use the location filter to narrow the list to the specific location.

"Sprint capacity does not change after adding a holiday" — the sprint is likely already closed. Closed sprints have frozen capacity. Only open sprints are recalculated when a holiday is added or removed.
Tip: At the start of each financial year, use Import to load the full year's public holidays for every location in one go. This takes a few minutes and ensures accurate capacity from the first sprint onwards.

Tags

Shared labels that group projects across programme boundaries for portfolio filtering.

Tags are simple, reusable labels from a shared library that can be applied to any project. They let you slice the portfolio in ways that cut across programmes — for example, tagging all cloud-related projects with cloud-migration regardless of which programme owns them.

Tags vs. Labels — what is the difference?
Tags come from a shared library and can be applied to any project. Use them for cross-portfolio categorisation (e.g. regulatory, high-risk, cloud-migration).
Labels are project-specific short identifiers defined directly on a project. Use them for internal reference codes unique to that one project. They do not appear in a shared library.

Actions on this page

Button / ActionWhat it does
Add TagCreate a new tag with a short, unique name (max 50 characters).
Edit Update the tag name. The change is reflected immediately on all projects that use it.
Delete Removes the tag from the library and unlinks it from every project that used it. This cannot be undone.
Import / ExportBulk-create tags from a spreadsheet, or download the tag library.

How to use

  1. Go to Tags and click Add Tag. Enter a concise, lowercase name and click Save.
  2. Open a project and go to the Tags field. Search for and select one or more tags.
  3. On the Projects list, use the Tags filter to find all projects with a given tag across all programmes.
Deleting a tag removes it from all projects. When you delete a tag from the library, it is immediately unlinked from every project that used it — with no confirmation step beyond the initial delete prompt. If in doubt, check which projects use the tag before deleting.
Tip: Agree on a tag vocabulary with your team before creating the library. Having cloud, cloud-migration, and Cloud Migration as three separate tags fragments your portfolio view. Pick one name per concept and stick to it.

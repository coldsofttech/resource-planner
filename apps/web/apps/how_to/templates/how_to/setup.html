Setup Guide

The setup wizard runs once when Resource Planner is first deployed. It writes your infrastructure configuration to a .env file, creates your admin account, switches the database, and stores secrets. Once complete it cannot be re-run from the UI — changes are made through the admin settings pages.

One-time process. Setup runs exactly once. Refreshing or navigating away mid-wizard is safe — the wizard resumes where it left off — but submitting the final step locks the wizard permanently. Make sure all values are correct before you click Finish.

Two phases

The wizard processes your input in two ordered phases. Understanding the boundary helps you predict what rolls back if something fails.

Phase 1 Environment

Writes infrastructure, database engine, and logging settings to .env. Switches the live database connection. Not rolled back on later failure.

Phase 2 Database (atomic)

Creates the admin user, saves app config, auth providers, storage and email settings in a single database transaction. All-or-nothing: if any step fails, the whole phase rolls back.

Before you begin

  • Resource Planner is running and reachable in a browser (/setup/ should load).
  • For PostgreSQL: the target database and a user with CREATEDB privileges already exist.
  • For AWS deployment: an IAM role or access key pair with secretsmanager:CreateSecret / PutSecretValue permissions is available.
  • For SAML: your IdP metadata (entity ID, SSO URL, X.509 certificate) is ready. The IdP must be reachable from the server running Resource Planner.
  • For OAuth: your provider's client ID, client secret, authorization, token, and userinfo endpoints are ready.
  • For SMTP email: server hostname, port, encryption type, and credentials (if required) are available. A test email will be sent during setup.
  • A Fernet encryption key is required for local deployments. Generate one now via GET /api/v1/setup/gen-key/ or the wizard's built-in generator.
1
Admin Account
Creates the first superuser — your primary management account.
Phase 2

This account has full access to every feature and all admin settings. Use a strong, unique password that is not shared with any other service.

FieldTypeRequiredNotes
first_nameTextYesMax 100 characters.
last_nameTextYesMax 100 characters.
emailEmailYesMust be a valid email address. Used to sign in.
passwordPasswordYesMinimum 12 characters, see rules below.

Password rules (all must pass):

  • At least 12 characters.
  • At least one uppercase letter (A–Z).
  • At least one lowercase letter (a–z).
  • At least one digit (0–9).
  • At least one symbol (any non-alphanumeric character).
Common errors

"Password must be at least 12 characters." — Use a longer password.

"Password must contain at least one uppercase letter." — Add an uppercase letter.

"Password must contain at least one symbol." — Add a symbol such as !, @, #, or $.

Email already exists — This should not occur during first setup. If you see it, the database already contains user records; the wizard may have been partially run before. Inspect the database directly.

Tip: Save these credentials in a password manager immediately. There is no in-app account recovery unless email has been configured — and email is configured later in the wizard.

App Settings
Sets the public-facing application name and canonical URL.
Phase 2
FieldTypeRequiredNotes
app_nameTextYesMax 50 characters. Shown in the browser tab, emails, and the top bar. Supports limited HTML: <b>, <strong>, <i>, <em>, <u>.
app_urlURLYesMax 100 characters. The canonical public URL (e.g. https://rp.example.com). Used in password-reset and notification emails. Must be a valid URL with a scheme.
Common errors

"Enter a valid URL." — app_url must include the scheme: https://rp.example.com, not rp.example.com.

Name appears truncated in emails — Keep app_name under 30 characters for best email client compatibility.

Tip: The app_url value is added to Django's ALLOWED_HOSTS automatically. If you later change the domain, update this setting in the admin configuration page and restart the server.

Infrastructure
Chooses how secrets are encrypted and where they are stored.
Phase 1

Choose Local if you are running on a single server or in a containerised environment without AWS. Choose AWS if you want credentials stored in AWS Secrets Manager.

Option A — Local deployment

FieldTypeRequiredNotes
deployment_typeChoiceYesSet to local.
fernet_keyText (secret)Yes44-character URL-safe base64 key ending in =. Generate one with the wizard's "Generate key" button or GET /api/v1/setup/gen-key/.

Option B — AWS deployment

FieldTypeRequiredNotes
deployment_typeChoiceYesSet to aws.
aws_regionTextYesAWS region code, e.g. eu-west-1, us-east-1, ap-southeast-2.
secrets_prefixTextYesPath prefix for all secrets, e.g. /resourceplanner/prod. Trailing slashes are stripped automatically.
aws_auth_modeChoiceYesrole — uses the EC2/ECS IAM role attached to the instance. user — uses an explicit access key pair.
aws_access_key_idText (secret)If aws_auth_mode=userExactly 20 uppercase alphanumeric characters, e.g. AKIAIOSFODNN7EXAMPLE.
aws_secret_access_keyText (secret)If aws_auth_mode=userExactly 40 characters — letters, digits, /, +, =.

With AWS deployment, the database password is stored as a secret under {secrets_prefix}/db. OAuth and SAML credentials are stored under {secrets_prefix}/oauth/{name}/… and {secrets_prefix}/saml/{name}/… respectively.

Common errors

"Enter a valid AWS region (e.g. eu-west-1, us-east-1, ap-southeast-2)." — The region must match the pattern xx-xxxx-n. Common mistake: eu-west1 (missing hyphen before digit).

"Enter a valid AWS Access Key ID (20 uppercase alphanumeric characters)." — The key is case-sensitive; it must be all uppercase and exactly 20 characters.

"Enter a valid AWS Secret Access Key (40 characters)." — Verify you copied the full key. AWS secret keys are exactly 40 characters.

Invalid Fernet key — The key must be generated by cryptography.fernet.Fernet.generate_key() or the wizard's generator. Do not use a self-typed passphrase.

Phase 1 writes succeed but Phase 2 fails — The .env file already has the Fernet key / AWS credentials written. You do not need to re-run Phase 1 — but if you re-submit the wizard, the Phase 1 values will be overwritten with whatever you enter again. Make sure to enter the same Fernet key if you retry.

Secret key safety. Back up the Fernet key immediately after setup. If it is lost and you used local deployment, all encrypted data (OAuth client secrets, SAML certificates) becomes unrecoverable.
4
Database
Connects to your database, runs migrations, and switches the live connection.
Phase 1

The wizard tests the connection before writing anything. On success it writes credentials to .env, rebuilds the Django database connection, and runs manage.py migrate automatically.

Option A — SQLite (development only)

FieldValue
enginesqlite

No further fields required. Uses the default db.sqlite3 file in the project root. Not suitable for production.

Option B — PostgreSQL (production)

FieldTypeRequiredNotes
engineChoiceYesSet to postgresql.
hostTextYesHostname or IP of the PostgreSQL server.
portTextYesDefault: 5432.
db_nameTextYesName of the target database. Must already exist.
user_nameTextYesDatabase user. Must have permission to create tables and run migrations.
passwordText (secret)YesDatabase user's password. Stored in .env (local) or Secrets Manager (AWS).
Test connection first. Use the "Test connection" button in the wizard (calls POST /api/v1/setup/test/db/) before submitting. This verifies connectivity with a 5-second timeout and gives you a clear success or failure message before any changes are written.
Common errors

"could not connect to server: Connection refused" — The PostgreSQL server is not running or host/port is wrong. Verify with psql -h <host> -p <port> -U <user> from the server running Resource Planner.

"FATAL: password authentication failed" — Wrong username or password. Check the credentials against your database server's pg_hba.conf.

"FATAL: database does not exist" — Create the database first: createdb -U postgres <db_name>.

"could not connect to server: Connection timed out" — A firewall is blocking the connection. Check security group rules if using AWS RDS, or pg_hba.conf if self-hosted.

"psycopg2 not installed" — Install the PostgreSQL driver: pip install psycopg2-binary.

Migrations fail mid-wizard — This is a Phase 1 failure. The .env was updated and the DB engine switched but migrations did not complete. Connect to the database and run python manage.py migrate manually, then re-submit the wizard.

Authentication
Configures how users sign in — Classic, OAuth, or SAML.
Phase 2

Choose the authentication mode that matches your organisation's identity strategy. Only one mode is active at a time. Connection tests run automatically before credentials are saved.

Option A — Classic (username & password)

FieldTypeRequiredNotes
auth_typeChoiceYesSet to classic.
self_registerBooleanYesIf true, anyone can create their own account at /register/. If false, only admins can create accounts.

No external connection test is performed for Classic auth.

Option B — OAuth 2.0

FieldTypeRequiredNotes
auth_typeChoiceYesSet to oauth.
provider_nameTextYesDisplay name, e.g. Google, Okta, Azure AD. Max 100 characters. Must be unique.
client_idText (secret)YesOAuth application client ID. Stored encrypted.
client_secretText (secret)YesOAuth application client secret. Stored encrypted.
auth_endpointURLYesAuthorization endpoint, e.g. https://accounts.google.com/o/oauth2/v2/auth.
token_endpointURLYesToken endpoint, e.g. https://oauth2.googleapis.com/token.
userinfo_endpointURLYesUserinfo endpoint, e.g. https://openidconnect.googleapis.com/v1/userinfo.
scopeTextYesSpace-separated scopes, e.g. openid email profile.
iconBootstrap Icon classNoOptional icon shown on the SSO button, e.g. bi-google.

How the OAuth connection test works: The wizard posts a request to your token_endpoint with a dummy authorization code (rp_test_probe). A valid configuration returns error: invalid_grant (wrong code — expected). If the server returns error: invalid_client, the client ID or secret is wrong. Then the wizard separately checks that the auth_endpoint is reachable.

idp_entity_idURLYesIdP entity ID from your IdP's metadata, e.g. https://your-idp.okta.com.
idp_sso_urlURLYesIdP single sign-on URL, e.g. https://your-idp.okta.com/sso/saml.
idp_x509_certText (secret)YesBase64 certificate body only — no -----BEGIN CERTIFICATE----- headers. Min 50 characters. Stored encrypted.
sp_entity_idURLNoService provider entity ID. Defaults to app_url if left blank.

iconBootstrap Icon classNoOptional icon shown on the SSO button.
Common errors — OAuth

"Token endpoint is reachable but the client credentials were rejected." — Check your Client ID and Client Secret against your OAuth application. They must match exactly — no extra spaces.

"Cannot reach token endpoint: <reason>" — The server running Resource Planner cannot reach token_endpoint. Check DNS resolution and firewall rules from the server.

"Cannot reach authorisation endpoint: <reason>" — Same as above for auth_endpoint.

Common errors — SAML

"Do not include the -----BEGIN CERTIFICATE----- header or footer" — Strip the PEM wrapper lines. Copy only the lines between them.

"Enter a valid base64-encoded X.509 certificate body." — The certificate body may contain line breaks from copy-paste. Remove all whitespace and newlines, leaving a continuous base64 string.

"IdP X.509 certificate expired on <date>." — Obtain an updated certificate from your IdP and re-enter it.

"Cannot reach IdP SSO URL: <reason>" — The server running Resource Planner cannot make outbound HTTP requests to your IdP. Ensure the IdP URL is accessible from the server's network.

6
Storage
Configures where uploaded files (avatars, attachments) are stored.
Phase 2
FieldTypeRequiredNotes
storage_typeChoiceYesdatabase — store files as BLOBs in the database (simple, not recommended for large deployments). filesystem — store files in a local directory. s3 — store files in an S3 bucket.
storage_pathTextIf filesystem or s3Filesystem: absolute path, e.g. /var/resourceplanner/media. The directory is created automatically. S3: full ARN, e.g. arn:aws:s3:::my-rp-bucket.
Common errors

"Enter a valid S3 bucket ARN (e.g. arn:aws:s3:::my-bucket)." — The ARN must start with arn:aws:s3::: followed by a valid bucket name (lowercase letters, digits, hyphens, dots, 3–63 characters).

Directory creation fails — If the filesystem path cannot be created (e.g. permission denied), the setup transaction rolls back. Ensure the process running Resource Planner has write access to the parent directory, or create the directory manually before setup.

S3 permissions required: The IAM role or user needs s3:PutObject, s3:GetObject, and s3:DeleteObject on the bucket. If using pre-signed URLs, also grant s3:GeneratePresignedUrl.

Phase 2

FieldTypeRequiredNotes
email_typeChoiceYesconsole — prints emails to server logs (development). smtp — sends real emails.
from_addressEmailYesThe From address on all outgoing emails, e.g. noreply@example.com.
from_nameTextYesThe From display name, e.g. Resource Planner.

SMTP-specific fields

FieldTypeRequiredNotes
smtp_hostTextYesSMTP server hostname, e.g. smtp.sendgrid.net.
smtp_portIntegerYesPort number 1–65535. Common: 587 (STARTTLS), 465 (SSL), 25 (none).
smtp_enc_typeChoiceYesnone, starttls, or ssl. Use starttls with port 587 or ssl with port 465.
smtp_auth_enabledBooleanNoEnable SMTP authentication. Default: false.
smtp_usernameTextIf smtp_auth_enabledSMTP login username.
smtp_passwordText (secret)If smtp_auth_enabledSMTP login password.

A test email is sent to from_address during setup with the subject "Resource Planner — Email Test". If it does not arrive, check your spam folder before concluding the configuration is wrong.

Common errors

"Connection refused" / "Network unreachable" — The SMTP host or port is wrong, or a firewall is blocking outbound connections on that port. Some cloud providers (AWS EC2, Google Cloud) block port 25 by default — use port 587 with STARTTLS.

"(535, 'Authentication credentials invalid')" — Wrong username or password. For Gmail, you need an App Password (not your regular password) and must enable "Less secure apps" or use OAuth SMTP.

"SSL: WRONG_VERSION_NUMBER" — Mismatch between smtp_enc_type and the actual port. Port 587 uses STARTTLS, port 465 uses SSL. Swapping them causes this error.

"STARTTLS extension not supported by server" — The server does not support STARTTLS. Switch to ssl on port 465, or none on port 25 (not recommended).

Test email not received — Check spam/junk folder. If using from_address that does not match your sending domain, SPF/DKIM alignment may cause the message to be silently dropped.

General troubleshooting

Setup loops back to the wizard after completion

The setup middleware redirects all traffic to /setup/ until SETUP_COMPLETE is True in the database.

Fix: If the Phase 2 transaction rolled back, the config key was never written. Check the server logs for the exception that caused the rollback, fix the underlying issue, and re-submit the wizard.

Phase 2 rolled back but Phase 1 already wrote .env

Phase 1 (infra, database, logging) is not transactional — if Phase 2 fails and you re-run, Phase 1 values will be overwritten with whatever you enter on the next attempt.

Fix: Keep a copy of all Phase 1 values (especially the Fernet key) and enter the same values on retry. If you used a different Fernet key on retry, all secrets encrypted with the old key will be unreadable.

AppRegistryNotReady / ImproperlyConfigured on startup

The DJANGO_SETTINGS_MODULE environment variable is not set, or the application is imported before Django is fully initialised.

Fix: Ensure DJANGO_SETTINGS_MODULE=config.settings is set before starting the server. With Docker, add it to the container's environment. Check pyproject.toml / manage.py for the correct module path.

AWS Secrets Manager: AccessDeniedException

The IAM user or role does not have permission to create or update secrets.

Fix: Attach a policy with at minimum: secretsmanager:CreateSecret, secretsmanager:PutSecretValue, secretsmanager:GetSecretValue, and secretsmanager:DescribeSecret for the resource ARN arn:aws:secretsmanager:<region>:<account>:secret:<prefix>/*.

Setup status stuck at "running"

The wizard polls GET /api/v1/setup/status/ every few seconds. If setup is killed mid-run the status never transitions to "complete" or "error".

Fix: Restart the application server. The in-memory status tracker resets on restart. Re-submit the wizard — it will re-run setup from scratch (Phase 1 values in .env persist, but the database transaction was rolled back by the crash).

Cannot bypass the setup redirect to reach /admin/ or /api/

The SetupMiddleware intercepts all traffic and redirects to /setup/ until setup is complete.

Exempt paths: /setup/, /login/, /api/v1/setup/, /api/v1/auth/, /static/, /media/. If you need emergency access to the Django admin, temporarily set SETUP_COMPLETE=True directly in the database and restart.

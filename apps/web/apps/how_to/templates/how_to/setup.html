Setting Up Resource Planner

The setup wizard runs once when you first deploy Resource Planner. It walks you through eight steps — creating your admin account, naming the app, choosing how secrets are stored, connecting your database, configuring sign-in, setting up file storage, connecting email, and enabling logging. Once complete, the wizard is locked and all further changes are made through the Settings pages inside the app.

One-time process. The wizard can only be completed once. Navigating away mid-wizard is safe — it resumes where you left off — but once you click Finish the wizard is permanently locked. Double-check all values before submitting.

How setup works

Setup runs in two phases. Understanding the difference matters if something goes wrong and you need to retry.

Phase 1 Environment

Writes your infrastructure, database, and logging choices to a configuration file on the server. These changes take effect immediately and are not rolled back if a later step fails.

Phase 2 Database

Creates your admin account and saves all other settings in a single database transaction. If any step in Phase 2 fails, everything from Phase 2 is rolled back automatically — you can fix the issue and retry.

Before you begin

  • Resource Planner is running and reachable in your browser — you should be able to open the setup wizard.
  • For PostgreSQL: the target database already exists and you have a database username and password with permission to create tables.
  • For AWS: an IAM role or access key with permission to create and update secrets in AWS Secrets Manager is available.
  • For OAuth sign-in (Google, Okta, Azure AD, etc.): your identity provider's client ID, client secret, and endpoint URLs are ready.
  • For SAML sign-in: your IdP's entity ID, SSO URL, and X.509 certificate are ready, and the IdP can reach your server's network.
  • For SMTP email: your mail server hostname, port, encryption type, and login credentials (if required) are available.
1
Create your admin account
The primary management account with full access to all features and settings.
Phase 2

Enter your first name, last name, email address, and a strong password. Your email address is used to sign in and must be valid. This account cannot be deleted and is the only account until you invite other users.

Your password must:

  • Be at least 12 characters long.
  • Include at least one uppercase letter (A–Z).
  • Include at least one lowercase letter (a–z).
  • Include at least one number (0–9).
  • Include at least one symbol — for example !, @, #, or $.
Save your credentials now. Store this email and password in a password manager before clicking Next. Password resets by email are only available after email is configured in Step 7 — there is no recovery option before then.
Common issues

"Password must be at least 12 characters" — Your password is too short. Try a passphrase with symbols.

"Password must contain at least one symbol" — Add a character such as !, @, or #.

"Email address already exists" — The database already has a user record. A previous setup attempt may have partially run. Check whether an admin account was created before retrying.

2
Name your instance
The public-facing name and URL for your Resource Planner deployment.
Phase 2

Give your instance a name and the web address where users will access it.

What to enterDetails
App name Shown in the browser tab, notification emails, and the top navigation bar. Examples: Resource Planner or Acme Delivery Hub. Keep it short for best email compatibility.
App URL The full web address users navigate to — must start with https:// or http://. Example: https://rp.acme.com. Used in password-reset links and system notifications.
Tip: The app URL is added to the server's allowed-host list automatically. If you move to a different domain later, update this in Settings and restart the server.
Common issues

"Enter a valid URL" — Make sure the address starts with https://. Writing rp.acme.com without the scheme will be rejected.

Name appears cut off in emails — Keep the app name under 30 characters for best compatibility with email clients.

3
Choose where secrets are stored
Controls how Resource Planner encrypts and stores sensitive credentials.
Phase 1

Resource Planner encrypts sensitive values — database passwords, OAuth credentials, and certificates. Choose where those encrypted secrets live.

Local deployment

Best for single-server and Docker deployments. Secrets are encrypted using a key stored on your server.

  • The wizard generates a secret encryption key for you — click Generate key to create one, or paste your own.
  • Copy this key immediately and save it somewhere secure (a secrets vault, password manager, or printed copy in a safe location). If it is lost, all encrypted data becomes unrecoverable.

AWS deployment

Choose this if you are running on AWS and want secrets managed centrally in AWS Secrets Manager.

What to enterDetails
AWS region The region your Secrets Manager is in, e.g. eu-west-1 or us-east-1.
Secrets path prefix A path prefix for all secrets created by Resource Planner, e.g. /resourceplanner/prod.
Authentication IAM role — uses the role attached to your EC2 or ECS instance automatically. Access key — enter an AWS access key ID and secret access key manually.
Back up your encryption key. For local deployments: once setup completes, copy the encryption key from your server's configuration file and store it somewhere safe outside the server. If the server is lost without a backup of this key, all encrypted credentials are permanently unrecoverable.
Common issues

"Invalid AWS region" — The region must follow the format xx-xxxx-n, e.g. eu-west-1. A common mistake is eu-west1 (missing hyphen before the digit).

"Invalid AWS Access Key ID" — The key must be exactly 20 uppercase characters. Check that you have not accidentally trimmed or lowercased it.

Phase 2 fails after Phase 1 succeeded — Phase 1 settings (including the encryption key) have already been written. If you retry, enter the same encryption key again — entering a different key will make previously encrypted data unreadable.

4
Connect your database
Choose your database engine and enter connection details.
Phase 1

The wizard tests the connection before writing anything. If the test passes, it saves the credentials, switches the live connection, and runs the database migrations automatically.

SQLite — for testing only

No connection details needed. Resource Planner uses a file on the server. Do not use SQLite in production — it does not support concurrent access or proper backups.

PostgreSQL — recommended for production

What to enterDetails
Host The hostname or IP address of your PostgreSQL server, e.g. db.acme.com or 10.0.0.5.
Port Default is 5432. Change only if your database runs on a non-standard port.
Database name The name of the database to use. It must already exist on the server.
Username A database user with permission to create tables and run migrations.
Password The database user's password.
Test the connection first. Click Test connection before proceeding. This checks your details with a short timeout and confirms connectivity before any changes are written.
Common issues

"Connection refused" — The database server is not running, or the host or port is incorrect. Verify the server is accessible from the machine running Resource Planner.

"Authentication failed" — The username or password is wrong. Double-check against your database server's user list.

"Database does not exist" — Create the target database on your PostgreSQL server first, then retry.

"Connection timed out" — A firewall or security group rule is blocking the connection. Check your network rules between the app server and the database server.

Migrations fail part-way through — Phase 1 settings were saved but migrations did not complete. Connect to your database directly and run migrations manually, then re-submit the wizard.

5
Choose how users sign in
Configure the sign-in method for your organisation — Classic, OAuth, or SAML.
Phase 2

Only one sign-in method is active at a time. You can change this later in Settings. The wizard runs a connection test for OAuth and SAML to confirm the provider is reachable before saving anything.

Classic — email and password

Users sign in with their email address and password. No external provider is needed.

  • Allow self-registration — if enabled, anyone can create their own account at the sign-up page. If disabled, only admins can create accounts.

OAuth — sign in with Google, Okta, Azure AD, or similar

Users sign in via an external identity provider. You will need the following from your provider's developer console.

What to enterWhere to find it
Provider name A label shown on the sign-in button, e.g. Google or Okta.
Client ID The application's client identifier from your OAuth provider.
Client secret The secret key paired with the client ID. Keep this confidential.
Authorisation endpoint The provider's URL that starts the sign-in flow. Found in the provider's documentation or OIDC discovery document.
Token endpoint The provider's URL for exchanging authorisation codes for tokens.
User info endpoint The URL Resource Planner calls to fetch the signed-in user's profile.
Scopes Permissions requested from the provider. At minimum: openid email profile.
How the connection test works: The wizard pings your token endpoint with a dummy request. A valid configuration returns an "invalid code" error — that is expected and means the provider is reachable and your credentials are accepted. An "invalid client" error means the client ID or secret is wrong.

SAML — enterprise single sign-on

Users sign in via your enterprise identity provider (e.g. Okta, Azure AD, ADFS). Collect the following from your IdP's admin console or metadata file.

What to enterWhere to find it
Provider name A label shown on the sign-in button, e.g. Okta.
IdP Entity ID Your identity provider's unique identifier, found in its SAML metadata. Usually a URL.
IdP SSO URL The URL Resource Planner redirects users to when they click Sign In.
IdP Certificate The X.509 certificate used to verify the IdP's SAML responses. Paste only the certificate body — remove the -----BEGIN CERTIFICATE----- and -----END CERTIFICATE----- lines, and remove any line breaks so it is one continuous string.
Assertion Consumer Service URL The URL your IdP will POST the SAML response to after a successful sign-in. Set this to your app URL followed by /saml/acs/, e.g. https://rp.acme.com/saml/acs/. Register this URL in your IdP application settings.
Common issues — OAuth

"Client credentials rejected" — The client ID or secret does not match what your provider has. Check for extra spaces or truncation when copying.

"Cannot reach endpoint" — The server running Resource Planner cannot make outbound HTTPS requests to your provider. Check firewall rules and DNS resolution.

Common issues — SAML

"Do not include the BEGIN CERTIFICATE header" — Strip the PEM header and footer lines, and remove all line breaks from the certificate body.

"Certificate body contains invalid characters" — The certificate may have picked up whitespace or newlines when copied. Paste it into a plain text editor, remove all whitespace, then re-paste.

"Certificate expired" — Obtain an updated certificate from your IdP and re-enter it.

6
Configure file storage
Choose where uploaded files — profile pictures and attachments — are stored.
Phase 2
OptionWhen to useWhat to enter
Database Simple deployments with few file uploads. Not recommended at scale. Nothing — files are stored directly in the database.
Filesystem Single-server deployments with a dedicated media folder. An absolute folder path on your server, e.g. /var/resourceplanner/media. The folder will be created if it does not exist.
Amazon S3 AWS deployments or any setup requiring scalable object storage. Your S3 bucket ARN, e.g. arn:aws:s3:::my-rp-files.
S3 permissions needed: The IAM role or user must have read, write, and delete permission on the bucket (s3:GetObject, s3:PutObject, s3:DeleteObject).
Common issues

"Enter a valid S3 bucket ARN" — The ARN must start with arn:aws:s3::: followed by a valid bucket name (letters, digits, hyphens, dots).

Filesystem path error — If the parent directory is not writable by the process running Resource Planner, the setup transaction will roll back. Create the directory and set the correct permissions, then retry.

7
Connect email
Configure how Resource Planner sends password-reset and notification emails.
Phase 2

Console — for development and testing

Emails are printed to the server log instead of delivered. Use this when setting up a development or staging environment. Enter a From address and display name — they appear in the log output.

SMTP — for production

Real email delivery. Enter the From address users will see in their inbox, then your SMTP server details.

What to enterDetails
From name Appears as the sender name in email clients, e.g. Resource Planner.
From address The email address outgoing emails are sent from, e.g. noreply@acme.com.
SMTP server Your mail server's hostname, e.g. smtp.sendgrid.net.
Port 587 with STARTTLS (recommended), 465 with SSL, or 25 without encryption.
Encryption Match this to your port: STARTTLS for 587, SSL for 465, None for 25.
Authentication Enable if your server requires a username and password to send mail.

A test email is sent to your From address during setup. If it does not arrive within a few minutes, check your spam folder before assuming the configuration is wrong.

Common SMTP providers:
ProviderHostPortEncryption
SendGridsmtp.sendgrid.net587STARTTLS
Mailgunsmtp.mailgun.org587STARTTLS
AWS SESemail-smtp.<region>.amazonaws.com587STARTTLS
Gmailsmtp.gmail.com587STARTTLS — requires an App Password
Microsoft 365smtp.office365.com587STARTTLS
Common issues

"Connection refused" or "Network unreachable" — The SMTP server or port is wrong, or a firewall is blocking outbound connections on that port. Some cloud providers block port 25 by default — use port 587.

"Authentication credentials invalid" — Wrong username or password. For Gmail, use an App Password — your regular Gmail password will not work.

"SSL: WRONG_VERSION_NUMBER" — Encryption type and port are mismatched. Port 587 needs STARTTLS; port 465 needs SSL.

Test email not received — Check your spam or junk folder. If the From address domain does not match your sending domain, SPF or DKIM failures may cause silent delivery failures.

8
Configure logging
Choose where the application writes its activity and error logs.
Phase 1
OptionWhat to enter
Local file A folder path on the server where log files are written, e.g. /var/log/resourceplanner. You can also configure rotation: daily, weekly, monthly, or when a file reaches a size limit.
Amazon S3 Your S3 bucket ARN where log files will be uploaded.
AWS CloudWatch Logs are streamed directly to CloudWatch Logs. No path is needed — the IAM role must have permission to create and write log streams.
Create the log folder before setup. Unlike the file storage folder, the log directory is not created automatically. Create the folder on your server and ensure the process running Resource Planner can write to it — otherwise the application will fail to start.
Rotation settings: For local logs, set rotation to Daily and keep 30 files as a reasonable starting point. Adjust based on how busy your instance is and how much disk space is available.

If something goes wrong

The app keeps redirecting me to the setup wizard

Resource Planner redirects all traffic to the setup wizard until setup is confirmed as complete in the database.

What to do: Check the server logs for an error that occurred during setup. The most common cause is a Phase 2 transaction rollback — fix the underlying issue (such as an unreachable SMTP server or a SAML certificate error) and re-submit the wizard.

I failed midway through and need to retry — will my settings be lost?

Phase 1 settings (infrastructure, database, logging) are written to the server immediately and are not rolled back. Phase 2 settings (admin account, auth, storage, email) roll back automatically if any step fails.

What to do: When retrying, enter the same encryption key you used the first time. Entering a different key will make any previously encrypted data unreadable. All Phase 2 steps can be re-submitted freely.

AWS: "Access Denied" when saving secrets

The IAM user or role does not have permission to create or update secrets in Secrets Manager.

What to do: Attach a policy granting at minimum secretsmanager:CreateSecret, secretsmanager:PutSecretValue, secretsmanager:GetSecretValue, and secretsmanager:DescribeSecret for the ARN pattern arn:aws:secretsmanager:<region>:<account>:secret:<prefix>/*.

Setup appears stuck at "running" and never finishes

The wizard polls for status every few seconds. If the server process was killed mid-run, the status never transitions to complete or error.

What to do: Restart the application server. The in-memory status resets on restart. Re-submit the wizard — Phase 1 settings already written to the server persist, but the database transaction was rolled back.

I cannot reach the login page or admin area

While setup is incomplete, all traffic is redirected to the wizard. A small number of paths are exempt: the wizard itself, the login page, setup API endpoints, and static files.

What to do: Complete setup or contact your server administrator to manually mark setup as complete in the database if a previous run finished but the confirmation was not saved.
